Configurar CI/CD Pipeline

En proceso

Configurar CI/CD Pipeline

Pipeline GitHub Actions para deploy automático a staging y production con tests automatizados.

Objetivos

  • Ejecutar tests en cada push y PR
  • Build y push de imagen Docker
  • Deploy automático a staging en merge a main
  • Deploy manual a production con approval

Pasos del workflow

  1. Checkout - Obtener código del repositorio
  2. Setup Python - Configurar Python 3.12 con cache de dependencias
  3. Install dependencies - uv sync con lockfile
  4. Run tests - uv run python manage.py test
  5. Lint & Type check - Ruff + MyPy
  6. Build Docker - Multi-stage build optimizado
  7. Deploy staging - Automático en merge a main
  8. Deploy production - Manual con approval

Configuración requerida

Secrets de GitHub necesarios:

  • DOCKER_REGISTRY - URL del registry
  • DOCKER_USERNAME / DOCKER_PASSWORD - Credenciales
  • STAGING_KUBECONFIG - Config kubectl staging
  • PROD_KUBECONFIG - Config kubectl production

Ejemplo de workflow

name: CI/CD Pipeline

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

env:
  REGISTRY: ghcr.io
  IMAGE_NAME: ${{ github.repository }}

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Setup Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.12'
          cache: 'uv'
      - name: Install dependencies
        run: uv sync --frozen
      - name: Run tests
        run: uv run python manage.py test
      - name: Lint
        run: uv run ruff check .
      - name: Type check
        run: uv run mypy src/

  build:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Build & Push
        uses: docker/build-push-action@v5
        with:
          push: true
          tags: ${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}:${{ github.sha }}

  deploy-staging:
    needs: build
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - name: Deploy to staging
        run: |
          kubectl set image deployment/tasksite tasksite=${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}:${{ github.sha }}
          -n staging

  deploy-production:
    needs: build
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    environment: production
    steps:
      - name: Deploy to production
        run: |
          kubectl set image deployment/tasksite tasksite=${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}:${{ github.sha }}
          -n production

Checklist

  • Configurar GitHub Actions workflow
  • Configurar secrets en repositorio
  • Tests pasando en CI
  • Deploy staging funcionando
  • Deploy production con approval

Nota: El pipeline usa uv para gestión de dependencias, lo que acelera significativamente los builds gracias al cache de lockfile.
